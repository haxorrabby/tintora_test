## Image orientation (root cause found and fixed)

**Symptom.** Most product photos extracted from the *América Foods* catalog
appeared upside-down on the site.

**Root cause.** The América PDF draws most of its embedded photos through a
vertically negated scale (the standard `[w 0 0 -h x y]` placement). PyMuPDF's
`pymupdf.Pixmap(doc, xref)` returns the *raw samples* exactly as stored in the
file, which — under that placement — are upside-down versions of what the page
actually shows. The importer was saving those raw samples, so ~230 files were
written upside-down. (The *Latinoandina* catalog is a flattened PDF; its photos
are page **renders**, which are upright by construction and were never affected.)

**Fix (in `apps/catalog/wholesale_import.py`, wired into the import command).**
Orientation is now derived at extraction time and self-validated:

- `orientation_from_pixels(raw, drawn)` compares the raw samples against the
  rendered page region under all 8 dihedral orientations and picks the best
  match (confident when the mean-abs-difference is ≤ 22 and beats the runner-up
  by ≥ 1.5). This pixel check is authoritative.
- `orientation_from_matrix(transform)` reads the placement matrix and is used
  only as a fallback when the pixel check is inconclusive (e.g. a near-uniform
  photo).
- `oriented_image_jpeg(...)` applies the resulting transform before writing the
  file, so new imports are correct at the source.
- No EXIF orientation tag is ever written (all files carry `Orientation = 1`);
  the pixels themselves are stored upright, so every renderer agrees.

**Repair of existing files.** `manage.py import_wholesale_catalogs
--fix-orientations` re-checks every stored image against its placement and
rewrites only the ones that do not match, **in place** (same file path, so the
image→product assignment in the database is untouched). Each pass is idempotent:
a file that already matches its placement is never rewritten, and a file whose
samples do not match its placement is first recovered by exact sample match
against every embedded image in the catalog before any rewrite.

Result of the repair run: **232** América image rows checked → **230** files
rewritten to the correct orientation, **2** recovered-and-fixed (ZN025, GO006),
**0** unresolved. The **382** Latinoandina photos were verified against their
own page renders (`ncc = 1.000` at identity) and needed no changes.
